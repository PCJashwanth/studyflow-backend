# StudyFlow

**An AI-powered academic schedule planner for university students.**
CSCI 4177/5709 · Group 2 · Dalhousie University

StudyFlow turns a student's courses, tasks, and weekly availability into a
concrete, explainable weekly study plan generated by an AI scheduler — and gives
instructors and administrators the oversight that generic planners lack. It is a
deployed three-tier application (React · Express · PostgreSQL) with three roles
on one codebase, secured by JWT, RBAC, and two-factor login.

## ✨ Features
**All roles:** email/password auth, **two-factor login** (emailed one-time code),
forgot/reset password, self-service profile (edit name/email, avatar, change
password).

**Student:** enroll in courses by code · manage tasks (type, deadline, effort,
priority) · set weekly availability · **generate an AI study schedule** with a
"why this block?" explanation on every block · week/month calendar · end-of-week
reflection.

**Instructor:** anonymized, aggregated **workload analytic** · create an
assignment that **fans out** to every enrolled student's task list.

**Administrator:** user management (create/edit/activate/deactivate, role
change) · course catalog by term with instructor assignment · course-request
approval · full **audit log**.

## 🏗️ Architecture
Three tiers, deployed independently:
- **Frontend** — React 19 + Vite, hosted on **Vercel**
- **Backend** — Node.js/Express REST API, hosted on **Render**
- **Database** — **Supabase** PostgreSQL via Prisma ORM
- **External services** — Groq (Llama 3.3) for scheduling, Resend for email

The AI scheduler follows a *propose → validate → fallback* pattern: the LLM
proposes a plan, a deterministic validator guarantees it fits real availability,
and a rule-based planner is the fallback if the model is unavailable.

## 🚀 Setup

### Prerequisites
- Node.js **≥ 20**
- A Supabase PostgreSQL database (or any Postgres)
- Optional: a Groq API key (AI) and a Resend API key (email) — both degrade
  gracefully if absent.

### Backend
```bash
git clone https://github.com/PCJashwanth/studyflow-backend
cd studyflow-backend
npm install
cp .env.example .env          # fill in the values (see below)
npm run prisma:generate
npm run prisma:deploy         # apply migrations
npm run seed                  # optional: one demo user per role + sample data
npm run dev                   # http://localhost:4000
```

**Backend environment variables (`.env`):**
```
NODE_ENV=development
PORT=4000
CORS_ORIGIN=http://localhost:5173     # comma-separated list allowed
JWT_SECRET=<openssl rand -hex 32>
JWT_EXPIRES_IN=7d
DATABASE_URL=<Supabase pooler, port 6543, ?pgbouncer=true>
DIRECT_URL=<Supabase direct, port 5432>   # used by migrations
GROQ_API_KEY=<optional>
GROQ_MODEL=llama-3.3-70b-versatile
RESEND_API_KEY=<optional>
RESEND_FROM=StudyFlow <onboarding@resend.dev>
MAIL_FROM=StudyFlow <onboarding@resend.dev>
CRON_SECRET=<openssl rand -hex 32>    # guards reminder dispatch
REMINDER_LEAD_HOURS=24
OTP_DEBUG_LOG=true                    # dev: print OTP codes to server logs
```

### Frontend
```bash
git clone https://github.com/ragenrunning/studyflow-frontend
cd studyflow-frontend
npm install
cp .env.example .env          # set VITE_API_URL=http://localhost:4000
npm run dev                   # http://localhost:5173
npm run build                 # production build → dist/
```

## 🔒 Security
JWT sessions · bcrypt password hashing · role-based access control middleware ·
two-factor login (bcrypt-hashed, single-use, 5-min, attempt-capped codes) · Zod
server-side validation · Prisma parameterized queries · CORS allowlist · helmet
security headers. Scanned with **OWASP ZAP**.

## ⚡ Performance
Client: route-level code-splitting, in-memory API cache, minified/gzipped Vite
build. Server: gzip compression, response caching on hot endpoints, composite
Postgres indexes. Load-tested with **Apache JMeter** (up to −85% response size,
−75% dashboard load).

## 🧾 Testing
Automated API tests (auth, RBAC, validation, cron guard) run in **GitHub Actions
